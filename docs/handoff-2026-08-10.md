## 3. 何がどこにあるか

- **HIR 最適化パス**（`NOCT_ENABLE_OPTIMIZER=ON`、level >= 2、実行順）:
  `hir_opt_abce.c`（multi-packed 対応済み）→ `hir_opt_simd.c`（新規）
  → `hir_opt_cse.c`（is_vector サブツリーをスキップ）→
  `hir_opt_typed.c`（新規、型格子）。
- **新オペコード**: bytecode.h の `OP_IADD`..`OP_FGTE`（22、typed）と
  `OP_VLOADI32X4`..`OP_VSHRI32X4`（13、SIMD）。連番前提のテーブル参照
  があるため**並びを崩さないこと**。シフト量と vreg 番号は imm8
  オペランド（u16 だと tmpvar フレームサイズ検証に落ちる）。
- **ヘルパ**: execution.c 末尾（常時コンパイル。プリコンパイル済み
  bytecode が最適化なしターゲットでも走るため）。宣言は
  include/noct/aot.h、エイリアスは interpreter.h / jit.h。
- **inline JIT**: jit-x86_64.c（typed 全 22 inline、SIMD は SysV +
  SSE4.1 CPUID ゲートで inline / **Win64 はヘルパ経路**）、
  jit-arm64.c（typed/SIMD とも inline、NEON はゲート不要）。残り 8
  バックエンドはヘルパ呼び（OP_PLOAD64 の前例踏襲）。
- **デバッグスイッチ**: `NOCT_TYPED_DEBUG` / `NOCT_TYPED_DISABLE` /
  `NOCT_SIMD_DEBUG`（vectorized/rejected(理由) を stderr 出力)/
  `NOCT_SIMD_DISABLE` / 既存の `NOCT_ABCE_DEBUG`。
- **テスト**: tests/typedop + run-typedop.sh(11 ケース)、tests/simd +
  run-simd.sh(13 ケース)。golden は level 0/2 × interp/JIT の 4 モード
  一致 + 発火/非発火アサーション（silent死の検出）。
  tests/abce/multi1-4、tests/syntax/64-cmp-rows・65-intmin-div も追加。

## 5. 今回修正した既存バグ (e19b229)

1. 比較ヘルパ: gt に src1=DOUBLE 行、neq に src1=LONG 行が欠落
   （double 左辺 / long != が実行時エラーだった）。neq の LONG 行は
   `a != b ⟺ !(a == b)` を保つため **eq の既存 int 変換
   （zero-extend）ごとミラー**している — eq 側の意味論の是非は
   別議論として温存。
2. INT_MIN / -1（long 版含む、% も）が SIGFPE でプロセスごと落ちて
   いた → typed ヘルパと同じラップ動作（div → min、mod → 0）。
3. **i386 JIT の OP_ASSIGN が rt_value 16 バイト中 8 バイトしか
   コピーしていなかった**（+12 の上位ワード欠落）。long/double が
   代入経由で全て壊れていた（2.5lf が 0 になる等）。LFCONST 疑いは
   誤りで、これが真因。
4. **RISC-V の条件分岐**: B-type 即値 ±4KiB が範囲チェックなしで
   黙って切り捨てられ、大関数で SIGILL（riscv32 のクラッシュ群）。
   ヘルパ呼び毎の例外チェックを BNE スキップ + JAL(±1MiB) に、
   パッチ対象分岐は 2 スロット確保で遠距離時に反転分岐 + JAL 展開。
   さらに **riscv64 はパッチの範囲チェックに `~` が抜けており、
   分岐を含む全関数の jit_build が失敗 → サイレントに
   インタプリタ実行だった**（修正後、riscv64 JIT は今回初めて実働。
   その状態で全スイート green を確認済み）。

## 6. 既知の制約・次にやるなら

- **packed をパラメータで受け取る関数のループはベクトル化されない**
  （element-type bet が関数内の生成ファクト由来のため uint8 に
  フォールバック → E1 reject）。画像カーネルはバッファ生成と同じ
  関数に書く必要がある。解消案: 関数間ファクト伝播、または
  02-typing の `packed` 注釈に要素型を持たせる拡張。**実用上最大の
  制約**なので次の一手に推奨。
- Win64 の SIMD inline 化（xmm6/7 退避のプロローグ手術が必要。
  現状ヘルパ経路で正しく動作、性能のみ劣る）。
- SIMD v1 の意図的スコープ外: reduction（E6）、counter-as-value
  （E5、IOTA 相当が必要）、本体内 if（E2、if-conversion）、
  f32x4（06 の Phase B、着手前に本ドキュメントのレビュー要）。
- CSE の eq int オペランド変換（(uint64_t)(uint32_t) zero-extend）は
  負の int と long の比較で数学的に不一致 — 仕様確認待ち。

  D-TOP12）。integer 除算のエラーは不変。golden への影響は無し
  （既存テストに該当ケースが無かった）。

## 8. 後続作業: big-endian JIT の数値条件修正

mips32 / mips64 / ppc32 の `OP_JMPIFTRUE` / `OP_JMPIFFALSE` は条件値を
常に `rt_value.val.i` として直接ロードしていた。big-endian では long の
下位ワード位置が異なるため、値 `1` の long 条件が false になり、
`syntax/48-numeric-cond` の while が0回で終了していた。

修正では `noct_ex_condition_helper()` に int / long / float / double の
真偽判定と非数値エラーを集約し、3バックエンドから三値（1 / 0 / -1）を
受けて分岐する。これによりワード順に依存せず、インタプリタと同じ
`Condition is not a number.` エラー経路も維持する。

検証済み: mips32 / mips64 / ppc32 の全 syntax を interpreter / JIT /
JIT+opt2 の3モード、x86_64 の syntax / typedop / simd、linux static /
MT-debug / mingw-x86_64 / msdos の各ビルド。変更は未コミット。

ABI 結論: SysV x86_64 と x86-32 の xmm0..7、AAPCS64 の v0..v7、
AAPCS32 の q8..q15、および PowerPC の v0..v7 はこの用途では volatile。
したがって退避不要。Win64 は direct scalar tier で volatile の xmm0 だけを
使い、nonvolatile の xmm6/xmm7 は使わないため、現状は同様に退避不要。
将来 Win64 を register-mapped native 化する場合だけ、prologue・通常
epilogue・例外 epilogue の対称な退避復元が必須。

QEMU-user では 10 JIT target の強制 long-branch、x86 の no-SSE/SSE2/
SSE4.1、ARM/PPC の SIMD/scalar、MIPS/RISC-V の direct scalar、および
bytecode metadata 往復を検証済み。全クロスビルド、MinGW、OpenWatcom、
native の syntax/typing/typedop/ABCE/CSE/SIMD/ctrans も green。QEMU-user
は指定CPUモデルのNEON/ASIMD/AltiVec命令を実行するため、機能確認は完了。
M5 Mac と POWER8 実機は性能測定を行う場合だけ必要で、完了ゲートではない。
